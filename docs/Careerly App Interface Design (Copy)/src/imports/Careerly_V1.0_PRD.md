## 一、产品概述

### 1.1 产品名称

Careerly

### 1.2 产品定位

> **Careerly 是一个帮助用户看见「岗位匹配距离」与「职业能力变化」的 AI 职业成长系统。**

它通过分析用户简历、职业经历以及目标岗位 JD，帮助用户：

- 看见当前能力与多个目标岗位之间的匹配关系与距离
- 理解自己距离目标岗位还有多少差距
- 追踪职业经历变化带来的能力变化与匹配变化
- 沉淀属于个人的长期职业资产

Careerly 不替用户决定职业方向，也不承诺直接提升用户价值。

### 1.3 产品一句话定义

> **Careerly 帮助用户通过 AI 看见自己的职业能力，理解自己与多个目标岗位之间的匹配关系，并持续追踪每一次变化。**

每一次简历、经历和能力证据的更新，都会转化为可见的匹配变化与职业资产积累。

### 1.4 产品浓缩表达

> **看见能力 · 理解匹配 · 追踪成长**

| 表达 | 回答的问题 | 对应产品层 |
|------|-----------|-----------|
| **看见能力** | 我的简历到底展现了什么能力？ | 职业资产（能力画像） |
| **理解匹配** | 我的能力与哪些岗位更匹配？距离多远？为什么？ | 多岗位匹配排序 |
| **追踪成长** | 我修改简历、新增经历之后发生了什么？ | 能力变化 + 匹配变化 + 历史沉淀 |

「理解匹配」同时点出了 AI 的角色：AI 不是计算一个分数，而是帮助用户理解为什么匹配、为什么不匹配、变化为什么发生。

### 1.5 产品核心价值：两个看见

「两个看见」是 Careerly 全部产品文档（01–06）的上层产品原则：

#### 看见一：我与目标岗位的距离

**解决：**

> "面对大量岗位，我到底更适合哪个方向？"

**通过：** 简历 × 多岗位 JD

**进行：**

- 岗位匹配分析
- 匹配度排序
- 能力匹配解释
- Gap 分析

**用户能够看到：**

- 当前最接近自己的岗位
- 与目标岗位之间的距离
- 为什么匹配
- 哪些能力影响匹配结果

#### 看见二：我自身的变化

**解决：**

> "我的经历和努力有没有让我变得更接近目标？"

**通过持续记录：**

- 工作经历变化
- 项目经历增加
- 技能补充
- 简历更新

**Careerly 帮助用户看到：**

- 能力资产变化
- 岗位匹配变化
- 职业成长趋势

#### 成长是结果，不是承诺

「成长」与「职业资产」是两个看见持续发生之后产生的**结果**，而不是 V1.0 需要直接承诺的独立功能。Careerly V1.0 始终围绕两个核心问题：

> ① 我现在离哪些岗位更近？
>
> ② 我的每一次变化，让自己离哪些岗位更近了？

### 1.6 产品愿景

> **成为每个职场人的 AI 职业成长伙伴，让职业成长从"碰运气"变成"可看见、可行动、可沉淀"。**

### 1.7 产品立场

Careerly 不替用户定义职业方向，也不评判用户的职业价值。

> **职业成长不是一次选择，而是一次次变化被看见、被理解、被积累的过程。**

Careerly 的立场由「两个看见」定义（见 1.5）：帮助用户看见自己与目标岗位的距离，看见自身的变化——成长本身，由用户自己完成。

## 二、AI 能力与边界

### 2.1 AI 在 Careerly 中的角色

Careerly 中的 AI 不是独立的聊天机器人，也不是替用户做职业决策的"职业裁判"。

> **AI 的核心职责：理解用户的职业信息，理解岗位的能力要求，建立两者之间的关系，并持续解释用户变化所产生的影响。**

AI 在产品中分为三层：

```
上层：AI 顾问与变化解释   —— 对话入口（AI Career Advisor）
中层：能力模型与匹配引擎 —— 用户能力模型 × 岗位能力模型
底层：AI 理解与分析引擎   —— 简历解析 / JD 解析 / Diff 比较
```

产品价值不来自"AI 给出答案"，而来自 **AI 让原本难以被看见的职业变化变得可理解、可比较、可追踪**。

### 2.2 AI 的五项核心能力

| # | 能力 | 说明 | 对应功能模块（03 文档） |
|---|------|------|------------------------|
| ① | 理解简历 | 将简历转化为结构化能力画像（经历、成果、技能、能力证据） | 简历解析模块 |
| ② | 理解岗位 JD | 将 JD 转化为岗位能力模型（核心/次级能力、权重） | 多岗位匹配排序模块 |
| ③ | 建立匹配关系 | 用户能力模型 × 岗位能力模型 → 匹配度、优势、Gap、多岗位排序 | 多岗位匹配排序模块 |
| ④ | 理解变化 | 新旧职业信息比较 → 能力证据变化 → 匹配度影响 | 历史分析系统 / 职业资产变化 |
| ⑤ | 解释变化 | 基于结构化 Diff 解释"为什么匹配 / 为什么变化" | AI 职业洞察模块 |

各能力的技术实现（LLM、Embedding 等）属于 AI System Design 范畴，不在本 PRD 展开。

### 2.3 AI 不负责什么

Careerly 的 AI **不**：

- 替用户决定职业方向，或判断用户"值多少钱"
- 保证用户获得工作、通过面试
- 替用户投递岗位或完成职业行动
- 凭空创造用户不存在的能力
- 将用户与其他求职者进行竞争排名
- 根据薪资、公司品牌、城市等非能力因素改变能力匹配排序

AI 是职业信息的**理解者、比较者和解释者**，不是"职业裁判"。

### 2.4 AI 的产品边界

基本原则：

> **有证据才判断，有变化才反馈，有数据才解释。**

AI 输出必须建立在用户真实提供的信息与系统已有数据之上：

```
用户输入 → AI 理解 → 结构化职业数据 → 能力模型 → 匹配关系 → 变化比较 → AI 解释
```

而不是"用户输入 → AI 自由生成 → 职业建议"。

**变化解释的精度边界：** 匹配度的变化解释基于新旧能力证据的**结构化差异（Diff）**给出，描述数据之间的关系；系统不承诺单项能力的因果归因精度（如"某能力 +8 导致匹配度恰好 +8%"）。

## 三、产品背景与行业机会

### 3.1 行业背景

随着职业环境变化，个人职业发展正在从：

> 单次求职行为

逐渐转向：

> 长期职业能力管理。

**过去：** 用户依赖招聘平台寻找机会。

**现在：** 用户越来越关注：

- 我的能力是什么？
- 我的优势在哪里？
- 我适合什么方向？
- 如何持续提升竞争力？

然而，目前职业产品仍主要围绕岗位搜索、简历优化、招聘匹配展开。缺少一个属于个人的：

> 职业能力认知与成长记录系统。

### 3.2 当前职业产品存在的问题

#### 问题 1：职业价值仍被外部标签定义

传统招聘体系通常通过学历、公司背景、职位名称、工作年限、薪资水平判断候选人价值。但这些信息无法完整体现：

- 可迁移能力
- 项目经验
- 专业能力积累
- 成长潜力

用户面临：

> "我的经历到底代表什么能力？"

而不是：

> "我曾经在哪里工作？"

#### 问题 2：岗位匹配缺少解释

目前多数招聘产品能够提供岗位推荐、匹配指数、简历评分。例如：

> 推荐指数 85%

但用户无法知道：

- 为什么是 85%
- 哪些能力匹配
- 哪些经历产生价值
- 哪些能力不足
- 如何缩小差距

用户得到的是**结果**，而不是**理解自身能力的方法**。

#### 问题 3：面对海量岗位，用户无法判断优先级

当前招聘市场岗位数量巨大、JD 信息复杂、岗位要求差异明显。用户通常依靠职位名称、公司品牌、薪资范围、主观判断选择岗位，但无法回答：

> "这些岗位中，哪个最符合我当前能力？"

#### 问题 4：职业成长过程缺少长期记录

用户经历项目增加、技能提升、工作变化、简历修改，这些变化通常无法形成连续记录。每次求职，用户都需要重新整理自己是谁、做过什么、有什么能力。过去的职业成长被分散在简历文件、项目资料、招聘记录中。

#### 问题 5：AI 职业工具仍停留在一次性服务

目前 AI 求职工具主要提供简历修改、面试模拟、岗位分析，但多数模式是：

```
用户提问 → AI 回答 → 结束
```

AI 不持续理解用户经历变化、能力变化、岗位目标变化。因此 AI 更像**临时工具**，而不是**长期职业伙伴**。

### 3.3 Careerly 产品机会

#### AI 发展带来的职业环境变化（调研）

多项权威调研指向同一结论：**AI 的发展正在加速职业能力结构的变化，职业管理正从"静态匹配"走向"动态追踪"。**

| 调研结论 | 数据 | 来源 |
|---------|------|------|
| 到 2030 年，39% 的岗位核心技能将发生变化 | 39% | 世界经济论坛《未来就业报告 2025》 |
| 86% 的雇主预计 AI 与信息处理技术将彻底改变其业务方式 | 86% | 同上 |
| 22% 的就业岗位处于变革浪潮（1.7 亿新增 / 9,200 万消失） | 22% | 同上 |
| 77% 的企业将"员工再培训与技能升级"列为最重要的人才策略 | 77% | 同上 |
| 员工使用 AI 辅助工作的比例：2023 年 30% → 2025 年 76% | — | 麦肯锡《AI 时代，职场未来的"变与不变"》2025 |
| 51% 的企业表示生成式 AI 降低了对入门级岗位的需求 | 51% | 麦肯锡 2025 新时代工作调研 |
| "AI 素养"成为岗位需求增速最快的技能，两年增长约 7 倍 | 7× | 麦肯锡全球研究院 2025 |
| 具备 AI 技能的劳动者享有约 56% 的工资溢价 | 56% | PwC AI Jobs Barometer 2025 |

调研揭示出三个对 Careerly 直接相关的趋势：

**① 技能半衰期缩短。** 岗位技能要求以前所未有的速度更新，"一次学习、终身受用"的职业模式失效。用户需要持续知道：**我离目标岗位的要求还差什么。**

**② 岗位能力要求被 AI 重写。** 重复性、入门级任务被 AI 吸收，岗位价值向"判断、解释、与 AI 协作"迁移。目标岗位的 JD 不是静态的——用户需要理解：**新要求与我当前能力的距离有多远。**

**③ 学习意愿与行动路径之间存在缺口。** 公众普遍感知到 AI 冲击并愿意学习调整，但缺少"从自身能力出发、知道学什么、能转化为什么"的明确路径。（参考：《人工智能就业影响公众认知指数》（AIEPI）调研）

这三个趋势与 Careerly 的「两个看见」直接对应：

- 技能快速变化 → Gap 被动态放大，用户更需要**看见自己与目标岗位的距离**；
- 岗位要求被重写 → 成长轨迹成为个人最重要的职业资产，用户更需要**看见自身能力的变化**。

与此同时，AI 的发展同样是 Careerly 的**技术前提**：大语言模型的能力成熟，使得"简历/JD 的结构化理解 + 变化解释"从高成本的人工咨询服务，第一次变为可规模化交付的产品能力。**AI 既制造了这个问题（职业结构加速变化），也提供了求解这个问题的工具（Careerly 的理解与解释引擎）。**

#### Careerly 的产品机会

Careerly 希望建立新的职业成长方式：

```
从寻找岗位
升级为：
理解能力 → 理解匹配 → 发现差距 → 记录变化 → 形成职业资产
```

Careerly 不创造用户价值，而是帮助用户：

- 发现价值
- 理解价值
- 记录价值变化

## 四、目标用户与用户痛点

### 4.1 目标用户

Careerly 面向正在探索职业方向、进行职业转型，以及希望持续管理职业成长的人群。

#### 用户 A：职业探索期用户

| 维度 | 描述 |
|------|------|
| **特征** | 工作经验较少；职业方向不明确；面对大量岗位缺少判断 |
| **场景** | "市场上这么多岗位，我不知道哪个适合我。" |
| **需求** | 了解自身能力；找到匹配方向；建立职业认知 |

#### 用户 B：职业转型用户（核心用户）

| 维度 | 描述 |
|------|------|
| **特征** | 已有工作经验；希望进入新的职业方向；原经历无法直接对应目标岗位 |
| **场景** | "我的经历能不能支持转型？距离目标岗位还有多少差距？" |
| **需求** | 转化已有经历价值；找到匹配岗位；理解能力 Gap |

转型示例：

- 建筑设计 → 产品经理
- 设计 → UX 产品
- 运营 → 增长产品

#### 用户 C：持续成长用户

| 维度 | 描述 |
|------|------|
| **特征** | 已明确职业方向；希望持续提升竞争力 |
| **场景** | "我最近的积累有没有让我更接近目标？" |
| **需求** | 保存职业经历；查看能力变化；管理职业资产 |

## 五、核心功能设计

Careerly V1.0 的核心功能围绕两个核心目标展开：

**目标一：** 帮助用户看见"我当前的能力更接近哪些岗位？" → 对应**多岗位匹配分析系统**

**目标二：** 帮助用户看见"我的能力是否正在发生变化？" → 对应**职业资产管理系统**

### 5.1 多岗位匹配分析（核心功能 P0）

#### 功能定位

多岗位匹配分析是 Careerly 的核心入口。它帮助用户将个人简历与多个目标岗位 JD 进行 AI 分析，最终回答：

> "在多个职业机会中，哪个岗位与我当前能力最匹配？"

#### 功能目标

解决用户：

- 不知道应该关注哪些岗位
- 不知道自己的经历适合什么方向
- 不知道距离目标岗位还有多远

#### 输入内容

**用户侧输入：**

**1. 简历**

来源：上传简历文件 / 手动编辑职业经历 / 历史职业资产

包含：工作经历、项目经历、技能、教育背景、成果描述

**2. 多个岗位 JD**

用户可以输入多个岗位链接、JD 文本、岗位描述。

例如：

| 岗位 | 描述 |
|------|------|
| 岗位 A | AI 产品经理 |
| 岗位 B | 用户增长产品经理 |
| 岗位 C | 数据产品经理 |

#### AI 分析流程

```
用户简历
  ↓
能力提取
  ↓
岗位 JD 解析
  ↓
岗位能力模型建立
  ↓
能力匹配计算
  ↓
生成排序结果
  ↓
解释匹配原因
  ↓
输出 Gap 分析
  ↓
AI 提升点
  ↓
AI 行动建议
```

#### 输出结果

**1. 岗位匹配排序**

核心展示：用户当前最接近的岗位。

示例：

| 排名 | 岗位 | 匹配度 |
|------|------|--------|
| 🥇 | AI 产品经理 | 86% |
| 🥈 | 产品经理 | 82% |
| 🥉 | 数据产品经理 | 74% |

**2. 匹配原因解释**

系统解释为什么某个岗位排名靠前。

例如：

> **AI 产品经理**
>
> **匹配优势：**
> - ✓ 产品规划经验
> - ✓ 用户研究能力
> - ✓ AI 项目经验
>
> **匹配来源：** 3 段工作经历、2 个项目经历、4 项技能

**3. 能力 Gap 分析**

展示当前能力 vs 岗位要求。

例如：

> **目标岗位：AI 产品经理**
>
> **已具备：**
> - ✓ 产品设计
> - ✓ 用户分析
>
> **待提升：**
> - △ AI 技术理解
> - △ 数据分析能力
>
> **当前 Gap：14%**

**4. 岗位距离**

用户可以直观看到自己距离目标岗位的位置。

例如：

> **当前状态：** AI 产品经理 86%
>
> **距离：** 高级 AI 产品经理 72%

**5. AI 需要提升的点**

基于当前岗位要求、用户已有能力和 Gap，AI 提炼最值得优先提升的能力。

- 不追求列出所有不足，而是聚焦对目标岗位匹配影响最大的 **1–3 项**
- 明确说明"为什么这一项值得提升"——依据来自前面的 Gap 分析，不是泛化建议

例如：

> **需要提升：AI Agent 产品落地能力**
>
> 当前已有 AI 产品项目经验，但缺少完整的 Agent 产品落地案例，是目前与该岗位要求之间的主要 Gap 之一。

**6. AI 行动建议**

基于需要提升的能力，给出下一步可执行的行动建议。

- 行动建议必须与用户当前能力基础和 Gap 相关，不给出脱离用户现状的通用建议
- 优先给出**具体、可验证、能够形成职业资产**的行动

例如：

> **下一步建议：**
> - 完成一个可实际运行的 AI Agent 项目
> - 在项目中补充需求分析、产品设计和效果评估
> - 将项目成果沉淀为可展示的项目经历
>
> 完成后重新分析，可以观察该能力以及相关岗位匹配度是否发生变化。

#### 输出结果的核心逻辑

Careerly 不应该停留在：

> **"你与这个岗位匹配 78%。"**

而应该继续回答：

> **"为什么是 78%？" → "还有哪些 Gap？" → "最值得提升什么？" → "下一步可以做什么？"**

最终形成完整链路：

```
匹配度 → 匹配原因 → 能力优势 → 能力 Gap → AI 提升点 → AI 行动建议
```

**边界声明：** Careerly 可以给出行动建议，但**不承诺这些行动一定会增加用户的真实职业价值**。用户真正完成行动后，Careerly 再通过新的简历、经历或项目记录去分析变化，并反馈到能力和岗位匹配度上——这才是"追踪成长"的闭环。

### 5.2 职业资产中心（核心功能 P0）

#### 功能定位

职业资产中心是 Careerly 长期价值的核心。它不是简单保存简历，而是：

> 用户职业能力变化的长期数据库。

#### 职业资产组成

**1. 简历资产**

记录不同时间版本的职业状态。

| 版本 | 时间 |
|------|------|
| Resume V1 | 2026.01 |
| Resume V2 | 2026.05 |
| Resume V3 | 2026.08 |

用户可以查看：经历变化、能力标签变化、匹配结果变化。

**2. 经历资产**

记录用户职业经历，包括：

- **工作经历：** 公司、职位、时间、工作内容
- **项目经历：** 项目名称、项目角色、项目成果
- **技能经历：** 技能新增、技能熟练度变化

**3. 能力资产**

Careerly 将用户经历转化为能力模型。

例如：

| 能力 | 评分 |
|------|------|
| 产品能力 | 85 |
| 用户研究能力 | 78 |
| AI 应用能力 | 72 |
| 数据分析能力 | 60 |

支持：能力评分、能力趋势、能力变化原因。

**4. 岗位资产**

记录用户分析过的所有岗位，包括 JD 内容、分析时间、匹配结果、历史变化。

示例：

| 项目 | 详情 |
|------|------|
| 岗位 | AI 产品经理 |
| 首次分析 | 2026.06 |
| 首次匹配度 | 72% |
| 最新分析 | 2026.08 |
| 最新匹配度 | 86% |
| 变化 | +14% |

**5. 成长资产**

记录职业变化产生的影响。

例如：

> **新增：AI Agent 项目**
>
> **产生：**
> - AI 能力 +8
> - 产品能力 +4
> - AI 产品经理匹配度 72% → 86%

### 5.3 历史分析系统

#### 功能定位

历史分析用于连接过去状态与当前状态，让用户看到：

> "我不是停留在原地，我正在发生变化。"

#### 保存内容

- **简历历史：** 历史简历版本、修改记录
- **岗位分析历史：** 分析过的 JD、匹配结果、Gap 分析
- **能力变化历史：**

| 时间 | AI 能力 | 变化 |
|------|---------|------|
| 2026.06 | 60 | — |
| 2026.08 | 72 | +12 |

### 5.4 AI 职业分析助手

#### 功能定位

AI 助手不是普通聊天机器人，它是：

> Careerly 职业分析结果的解释层。

AI 的完整职责边界与三层架构（理解引擎 / 匹配引擎 / 顾问入口）见 **第二章「AI 能力与边界」**，本节仅定义其面向用户的交互能力。

#### 核心能力

**1. 解释匹配结果**

| 角色 | 对话 |
|------|------|
| 用户 | 为什么 AI 产品经理排名第一？ |
| AI | 因为你的经历中：产品规划经验较强、有 AI 项目案例、用户研究能力匹配。但缺少：商业化经验。 |

**2. 分析能力变化**

| 角色 | 对话 |
|------|------|
| 用户 | 为什么我的匹配度提高？ |
| AI | 相比上一次：新增 AI 项目经历，提升了 AI 应用能力和产品实践能力。因此 AI 产品经理匹配度从 78% 提升至 86%。 |

**3. 提供职业洞察**

例如：

> 根据你的经历，你当前更适合 AI 产品方向，其次为用户增长方向。建议关注 AI 应用落地经验积累。

## 六、核心业务流程

Careerly 不采用一次性分析模式，而采用**持续反馈循环**。

### 6.1 首次使用流程

```
用户注册
  ↓
上传简历
  ↓
输入多个目标岗位 JD
  ↓
AI 分析
  ↓
生成岗位匹配排序
  ↓
查看：匹配度 / 优势 / Gap
  ↓
保存职业资产
```

### 6.2 持续成长流程

```
用户新增经历
  ↓
修改简历
  ↓
重新分析岗位
  ↓
生成新的匹配结果
  ↓
比较历史变化
  ↓
更新职业资产
  ↓
形成成长轨迹
```

### 6.3 Careerly 核心循环

```
See（看见当前职业位置）
  ↓
Gap（理解距离目标差距）
  ↓
Change（用户经历产生变化）
  ↓
Grow（职业资产增长）
  ↓
再次 See（看到新的职业状态）
```

## 八、页面需求

Careerly 的页面架构围绕两个核心"看见"展开：

1. **看见匹配：** 看见当前简历与多个目标岗位之间的匹配度、排序以及距离。
2. **看见变化：** 看见简历与职业经历变化后，个人能力与历史岗位匹配度发生了什么变化。

四个一级页面分别承担不同职责：

> **首页｜看见现在**
> **分析｜看见距离**
> **AI｜理解与行动**
> **我的｜沉淀积累**

---

### 8.1 首页｜看见现在

**核心目标**

让用户打开 Careerly 后，快速了解：

> **我现在的职业状态怎么样？最近发生了什么变化？下一步可以做什么？**

首页采用"**总 → 分 → 变化**"的信息结构，不承担完整分析功能，而是作为整个职业成长循环的总览入口。

**主要模块**

#### 8.1.1 职业概览

展示当前最核心的职业状态。

包括：

* 当前最高岗位匹配度
* 当前最匹配岗位
* 与上次分析相比的变化
* 最近一次重要能力变化

示例：

> AI 产品经理
> 匹配度 86%
> 较上次 +8%

> 注：Careerly 不设置"职业资产指数""职业价值分数"等用于评价用户绝对职业价值的指标。

---

#### 8.1.2 行动建议

展示当前最值得用户关注的一项行动建议。

例如：

> 补充 AI Agent 项目经历
> 当前多个目标岗位均存在相关能力 Gap。

支持：

> **问问 AI**

进入 AI 职业顾问，并自动携带当前分析上下文。

---

#### 8.1.3 当前状态

展示当前用户与目标岗位之间的整体匹配状态。

包括：

* 当前最匹配岗位
* 当前匹配度
* 当前岗位排名
* 与上次分析相比的变化

支持进入：

> **分析 → 多岗位匹配结果**

---

#### 8.1.4 最近成长

展示用户最近发生的职业变化。

包括：

* 新增工作经历
* 新增项目经历
* 新增技能
* 简历内容变化
* 能力变化
* 因能力变化产生的岗位匹配变化

示例：

> 新增 AI Agent 项目
> AI 应用能力 68 → 76
> 相关岗位匹配度最高提升 +8%

支持进入：

> **我的 → 职业资产**

---

#### 8.1.5 今日一句

作为轻量级成长陪伴内容。

内容围绕：

* 职业成长
* 能力积累
* 自我认识
* 长期发展
* 行动与选择

该模块属于辅助体验，不承担核心产品功能。

MVP 阶段可以使用预置内容，不依赖实时 AI 生成。

---

#### 8.1.6 岗位匹配变化

展示用户近期分析过的岗位发生了什么变化。

重点展示：

* 岗位名称
* 当前匹配度
* 上次匹配度
* 匹配度变化
* 排名变化

示例：

> AI 产品经理 78% → 86% ↑8
> 产品经理 79% → 82% ↑3
> 数据产品经理 74% → 74% —

首页只展示变化摘要。

用户可以进入：

> **分析 → 多岗位匹配结果**

或：

> **我的 → 历史分析**

查看完整历史。

---

### 8.2 分析｜看见距离

**核心目标**

帮助用户回答：

> **"我的当前简历与多个目标岗位分别有多匹配？我离哪个岗位更近？"**

分析是 Careerly 的核心功能页面。

---

#### 8.2.1 简历输入区域

支持：

* 上传简历
* 更新当前简历
* 选择历史简历版本
* 查看当前使用的简历

当用户上传新简历后，Careerly 应识别简历内容变化，并重新计算相关岗位匹配结果。

---

#### 8.2.2 岗位输入区域

支持：

* 输入单个岗位 JD
* 批量输入多个岗位 JD
* 添加岗位链接
* 选择历史分析过的岗位

多个岗位进入同一次分析后，系统统一计算匹配度并进行排序。

---

#### 8.2.3 多岗位匹配结果

这是 Careerly 的核心结果页面。

用户可以直观看到：

* 岗位名称
* 匹配度
* 当前排名
* 与上次相比的匹配度变化
* 与上次相比的排名变化

示例：

| 排名 | 岗位      | 匹配度 | 变化 |
| -- | ------- | --: | -: |
| #1 | AI 产品经理 | 86% | ↑8 |
| #2 | 产品经理    | 82% | ↑3 |
| #3 | 数据产品经理  | 74% |  — |

核心体验：

> **让用户知道"现在的我更接近哪个岗位"。**

---

#### 8.2.4 岗位匹配详情

点击任意岗位后进入详情页面。

**匹配概览**

* 岗位名称
* 公司
* 匹配度
* 当前排名
* 匹配度变化

**匹配原因**

说明当前简历中哪些经历、项目、技能与岗位要求产生匹配。

**能力优势**

展示用户已经具备、且对该岗位匹配有重要影响的能力。

**能力 Gap**

展示当前岗位要求与用户已有能力之间的主要差距。

**AI 需要提升的点**

AI 根据岗位要求、用户当前能力和 Gap，提炼当前最值得关注的能力。

**AI 行动建议**

给出与 Gap 对应的具体行动建议。

例如：

> 完成一个 AI Agent 项目，并补充需求分析、产品设计和项目结果，形成新的能力证据。

支持：

> **问问 AI**

进入 AI 职业顾问继续讨论。

---

#### 8.2.5 实时重新分析

当用户更新简历后，系统需要重新分析已保存的历史岗位。

流程：

> 新简历
> ↓
> AI 解析变化
> ↓
> 更新能力模型
> ↓
> 重新计算历史岗位
> ↓
> 更新匹配度
> ↓
> 更新岗位排序
> ↓
> 记录变化

用户可以看到：

> **自己的变化是否让某些目标岗位更接近了。**

例如：

> AI 产品经理
> 78% → 86% ↑8

这构成 Careerly 的核心反馈闭环。

---

### 8.3 AI｜理解与行动

**核心目标**

帮助用户理解分析结果，并将分析结果转化为下一步行动。

**核心问题**

> **"为什么？下一步怎么办？"**

AI 不负责替代 Careerly 的核心匹配结果，而是负责：

* 解释匹配结果
* 解释能力 Gap
* 解释能力变化
* 分析变化可能产生的影响
* 给出提升方向
* 给出行动建议
* 与用户讨论职业问题

---

#### 8.3.1 AI 职业顾问

用户可以围绕当前职业状态进行自然语言提问。

例如：

* 为什么这个岗位匹配度最高？
* 我的主要 Gap 是什么？
* 哪个能力最值得优先提升？
* 如果我增加这个项目经历，会影响哪些岗位？
* 最近我的能力发生了什么变化？
* 我下一步应该做什么？

---

#### 8.3.2 上下文 AI

从首页、分析页面进入 AI 时，需要自动携带相关上下文。

例如从岗位详情进入：

> 当前简历 + 当前岗位 JD + 匹配结果 + 能力模型 + Gap + AI 建议

用户无需重复输入。

---

#### 8.3.3 AI 对话记录

记录：

* 用户问题
* AI 回复
* 对话时间
* 对话相关分析上下文

MVP 阶段采用轻量级历史记录即可。

---

### 8.4 我的｜沉淀积累

**核心目标**

帮助用户长期保存和理解自己的职业经历、能力与分析记录。

**核心问题**

> **"一路走来，我积累了什么？发生了什么变化？"**

"我的"不是传统意义上的个人设置页面，而是 Careerly 的：

> **个人职业档案与职业资产中心。**

---

#### 8.4.1 职业资产

展示用户长期积累的职业信息。

包括：

* 能力
* 工作经历
* 项目经历
* 技能
* 能力变化

职业资产应尽可能通过用户已有数据自动沉淀，而不是要求用户重复维护。

---

#### 8.4.2 能力变化

展示不同时间节点之间的能力变化。

例如：

> AI 应用能力
> 68 → 76 ↑8

> 产品规划能力
> 72 → 78 ↑6

同时说明变化来源，例如：

> 新增 AI Agent 项目经历

并进一步展示：

> 该能力变化使 AI 产品经理岗位匹配度从 78% 提升至 86%。

---

#### 8.4.3 简历

包括：

* 当前简历
* 历史简历版本

每次用户上传新的简历版本后，系统自动保存历史版本。

历史版本可以关联：

* 当时的能力状态
* 当时分析过的岗位
* 当时的匹配结果

---

#### 8.4.4 历史分析

历史分析用于沉淀用户过去进行过的职业分析。

包括：

* 历史岗位 JD
* 历史匹配结果
* 历史分析时间
* 当时使用的简历版本

例如同一个岗位：

> 2026-08-10：72%
> 2026-08-18：78%
> 2026-08-27：86%

用户可以看到自己的能力变化如何影响同一个目标岗位的匹配结果。

---

#### 8.4.5 历史岗位 JD

所有经过 Careerly 分析的岗位 JD 可以自动进入历史记录。

保存：

* 岗位名称
* 公司
* JD 内容
* 分析时间
* 使用的简历版本
* 当时匹配度
* 当前匹配度

这样用户可以持续建立自己的：

> **目标岗位数据库。**

---

#### 8.4.6 设置

包括：

* 账户
* 数据管理
* 隐私
* AI 设置
* 通知
* 关于 Careerly

设置不属于 Careerly 的核心产品价值，应保持低层级、低干扰。

---

### 8.5 页面之间的核心关系

Careerly 四个一级页面不是相互独立的功能模块，而是形成完整的职业成长反馈循环。

```text
首页｜看见现在
      ↓
分析｜看见距离
      ↓
AI｜理解与行动
      ↓
用户产生新的经历 / 能力
      ↓
更新简历
      ↓
重新分析
      ↓
岗位匹配变化
      ↓
职业资产变化
      ↓
我的｜沉淀积累
      ↓
回到首页
```

### 8.6 页面职责总结

| 页面 | 核心问题        | 核心职责           |
| -- | ----------- | -------------- |
| 首页 | 我现在怎么样？     | 当前职业状态总览       |
| 分析 | 我离哪些岗位更近？   | 多岗位匹配、排序、Gap   |
| AI | 为什么？下一步怎么办？ | 理解、解释、行动       |
| 我的 | 我积累了什么？     | 职业资产、历史记录、能力变化 |

---

### 8.7 页面信息层级原则

Careerly 页面不追求展示所有信息，而遵循：

> **首页看变化 → 分析看原因 → AI看行动 → 我的看积累**

具体而言：

* 首页：展示摘要和变化
* 分析：展示匹配与 Gap
* AI：解释并给出行动
* 我的：保存长期历史与职业资产

避免同一信息在多个页面完整重复。

---

### 8.8 页面需求与产品核心价值的对应关系

Careerly 的页面必须能够支撑两个核心可见：

**核心可见一：岗位匹配**

```text
简历
↓
多个岗位 JD
↓
匹配分析
↓
实时排序
↓
匹配度
↓
匹配原因
↓
能力 Gap
```

用户最终可以看见：

> **"现在的我，更接近哪个岗位。"**

---

**核心可见二：个人变化**

```text
旧简历
↓
新简历
↓
识别新增 / 修改内容
↓
能力变化
↓
重新分析历史岗位
↓
匹配度变化
↓
岗位排名变化
```

用户最终可以看见：

> **"我最近的积累，让自己发生了什么变化，以及离目标岗位更近了多少。"**

---

### 8.9 产品不提供的页面能力

Careerly 不建立以下页面或指标：

* 用户职业价值绝对评分
* 与其他用户的职业排名
* 薪资价值评分
* "成功概率"绝对预测
* 以学历、公司、城市等背景因素定义用户职业价值的综合指数

Careerly 的核心不是告诉用户：

> **"你值多少钱。"**

而是让用户看见：

> **"你的简历现在与哪些岗位更匹配，以及你的能力变化是否让自己更接近目标。"**

---

### 8.10 页面需求最终原则

Careerly 所有页面最终围绕四句话展开：

> **首页｜看见现在**
> **分析｜看见距离**
> **AI｜理解与行动**
> **我的｜沉淀积累**

并共同服务于两个核心结果：

> **看见匹配。**
> **看见变化。**

## 九、数据模型设计

Careerly 的核心数据资产不是岗位数据，而是：

> 用户职业能力与职业变化数据。

核心数据模型围绕以下链路建立：

```
用户 → 简历 → 经历 → 能力 → 岗位 → 匹配结果 → 成长变化
```

### 9.1 User 用户模型

**基础信息：**

| 字段 | 说明 |
|------|------|
| id | 用户 ID |
| name | 用户名 |
| avatar | 头像 |
| create_time | 创建时间 |

### 9.2 Resume 简历资产模型

用于保存用户不同阶段职业状态。

| 字段 | 说明 |
|------|------|
| id | 简历 ID |
| user_id | 用户 ID |
| version | 版本号 |
| content | 简历内容 |
| create_time | 创建时间 |
| update_time | 更新时间 |

包含：工作经历、项目经历、技能、教育背景。支持历史版本管理。

### 9.3 Experience 经历模型

记录用户职业经历。

**类型：** Work（工作）/ Project（项目）/ Skill（技能）

| 字段 | 说明 |
|------|------|
| id | 经历 ID |
| user_id | 用户 ID |
| type | 经历类型 |
| title | 标题 |
| description | 描述 |
| time | 时间 |
| impact | 影响 |

例如：

> **项目：** AI 招聘助手  
> **角色：** 产品负责人  
> **成果：** 提升匹配效率

### 9.4 Skill 能力模型

记录用户能力资产。

| 字段 | 说明 |
|------|------|
| id | 能力 ID |
| user_id | 用户 ID |
| name | 能力名称 |
| level | 能力等级 |
| trend | 变化趋势 |
| source | 来源 |

例如：

> **产品设计能力** 85 ↑ +5  
> **来源：** 新增项目经历

### 9.5 Job JD 岗位模型

保存用户分析过的岗位。

| 字段 | 说明 |
|------|------|
| id | 岗位 ID |
| company | 公司 |
| title | 职位名称 |
| description | 岗位描述 |
| requirements | 岗位要求 |
| create_time | 创建时间 |

### 9.6 MatchResult 匹配结果模型

保存简历与岗位之间的关系。

| 字段 | 说明 |
|------|------|
| id | 结果 ID |
| resume_id | 简历 ID |
| job_id | 岗位 ID |
| score | 匹配度 |
| advantages | 优势 |
| gaps | 差距 |
| analysis_time | 分析时间 |

例如：

> **AI 产品经理**  
> **匹配度：** 86%  
> **优势：** AI 项目经验  
> **Gap：** 商业化经验

### 9.7 CareerAsset 职业资产模型

CareerAsset 是 Careerly 的核心数据，用于描述用户职业状态变化。

| 字段 | 说明 |
|------|------|
| user_id | 用户 ID |
| asset_type | 资产类型 |
| value | 当前值 |
| change | 变化量 |
| time | 时间 |

例如：

> **AI 能力** 60 → 72 +12

### 9.8 GrowthRecord 成长记录模型

记录用户职业变化事件。

| 字段 | 说明 |
|------|------|
| id | 记录 ID |
| user_id | 用户 ID |
| event | 事件 |
| impact | 影响 |
| time | 时间 |

例如：

> **新增 AI Agent 项目**  
> **影响：** AI 能力提升、岗位匹配度提升 8%

## 十一、用户体验设计

### 11.1 核心场景验证

**核心场景：修改简历**

用户修改简历后，重新进行岗位匹配分析，对比历史结果，验证职业成长。

**意义：** 验证长期使用价值——用户通过持续更新简历，看到自身能力变化与岗位匹配度提升，形成正向反馈循环。

---

## 十二、视觉与交互设计

|------|------|

例如：

> 点击 → 为什么提升？  
> 查看 → 能力变化来源

## 十四、未来产品发展方向

Careerly 长期目标：成为个人职业成长基础设施。

### 阶段 3：职业机会系统

**能力：** 岗位发现、主动推荐、职业机会管理。

## 最终产品定位

> Careerly 是每个职场人的 AI 职业成长系统：帮助用户看见「岗位匹配距离」与「职业能力变化」，并沉淀个人职业资产。

**核心价值链：**

```
看见能力
  ↓
理解匹配
  ↓
追踪成长
  ↓
形成职业资产
```

让职业成长从"不确定的尝试"变成"可看见、可理解、可沉淀的长期过程"。
