# 1. 文档概述

## 1.1 文档目的

本文件定义 Careerly V2.0 的完整信息架构（IA）、页面层级、页面职责、导航关系和核心交互路径。

本版本不在旧 IA 基础上进行局部修补，而是根据 Careerly 当前已经确定的产品逻辑重新推导。

Careerly 的 IA 不以“功能模块”为中心，而以用户的认知路径为中心：

> **看见现在 → 看见距离 → 理解与行动 → 沉淀积累**

对应四个一级导航：

> **首页｜看见现在**
> **分析｜看见距离**
> **AI｜理解与行动**
> **我的｜沉淀积累**

---

# 2. IA 核心设计原则

## 2.1 以用户问题而非功能组织信息

Careerly 不应该要求用户理解产品内部有哪些功能，而应该围绕用户自然产生的问题组织页面。

核心问题：

1. **我现在怎么样？**
2. **我与哪些岗位更匹配？**
3. **我为什么匹配 / 不匹配？**
4. **我下一步可以做什么？**
5. **我最近发生了什么变化？**
6. **我一路积累了什么？**

---

## 2.2 两个核心“看见”

Careerly V2.0 的 IA 必须围绕两个核心可视化价值建立：

### 看见一：看见我与岗位的距离

用户可以通过一份简历与多个目标岗位 JD 的分析，看到：

* 哪些岗位更匹配
* 当前匹配度
* 岗位排序
* 匹配原因
* 能力优势
* 能力 Gap
* 距离目标岗位还有多远

核心功能：

> **多岗位匹配分析与实时排序**

---

### 看见二：看见我自身的变化

用户更新简历、工作经历、项目经历、技能或成果后，可以看到：

* 哪些能力发生变化
* 哪些能力得到增强
* 哪些历史岗位匹配度提升
* 哪些岗位排名发生变化
* 职业资产如何积累

核心功能：

> **职业资产变化与历史分析追踪**

---

## 2.3 成长不是一个独立功能，而是产品结果

“成长”不再作为一级导航。

原因：

> **成长不是 Careerly 中一个独立的数据模块，而是用户持续发生变化之后形成的结果。**

因此成长贯穿：

* 首页：最近成长
* 分析：匹配变化
* AI：行动建议
* 我的：能力变化 / 职业资产

形成：

```text
用户变化
↓
能力变化
↓
岗位匹配变化
↓
成长被看见
↓
沉淀为职业资产
```

---

## 2.4 首页不是 Dashboard

首页的任务不是展示所有数据，而是提供：

> **当前职业状态的一次总览。**

首页遵循：

> **总 → 分 → 变化**

结构：

```text
职业概览
↓
四张核心卡片
↓
岗位匹配变化
```

---

## 2.5 职业资产自动沉淀

职业资产不是要求用户主动维护的数据库。

用户在 Careerly 中：

* 上传简历
* 修改经历
* 添加项目
* 添加技能
* 分析岗位

这些行为产生的数据应该自动进入职业档案。

原则：

> **自动记录，而不是主动维护。**

# 5. 首页｜看见现在

## 5.1 页面定位

首页是 Careerly 的：

> **职业状态总览。**

不是完整的数据 Dashboard，也不是所有功能的入口集合。

核心目标：

> **让用户打开 App 后，在最短时间内知道“我现在怎么样、下一步做什么、最近发生了什么”。**

---

# 5.2 首页信息结构

首页采用：

> **总 → 分 → 变化**

```text
┌─────────────────────────┐
│       职业概览           │
│                         │
│ 当前最高岗位匹配 86%     │
│ AI 产品经理              │
│ 较上次 +8%               │
└─────────────────────────┘

┌────────────┬────────────┐
│  行动建议   │  当前状态   │
│             │             │
│ 下一步做什么 │ 我现在怎样   │
└────────────┴────────────┘

┌────────────┬────────────┐
│  最近成长   │   今日一句   │
│             │             │
│ 我最近变化   │ 成长陪伴     │
└────────────┴────────────┘

┌─────────────────────────┐
│       岗位匹配变化       │
│                         │
│ AI产品经理       ↑ 8%   │
│ 产品经理         ↑ 3%   │
│ 数据产品经理       —     │
│                         │
│        查看全部 →        │
└─────────────────────────┘
```

# 5.3 职业概览

### 页面职责

展示用户当前最重要的职业状态。

### 建议内容

* 当前最高岗位匹配度
* 当前最匹配岗位
* 相比上次分析的变化
* 最近能力变化

### 示例

```text
职业概览

AI 产品经理
86% 匹配

较上次分析 ↑ 8%

最近能力变化 +2
```

### 设计约束

不建议设计：

> “你的职业价值：86分”

原因：

Careerly 不应该人为创造一个代表用户职业价值的绝对分数。

应该使用事实型指标：

> **当前岗位匹配度**

---

# 5.4 行动建议卡片

### 核心问题

> **我现在最值得做什么？**

### 内容

展示当前最重要的一项行动建议。

例如：

> **补充 AI Agent 项目案例**

辅助说明：

> 该经历可以补强你当前 3 个目标岗位中的关键能力 Gap。

### 操作

主操作：

> **问问 AI**

跳转：

```text
首页
↓
行动建议
↓
AI
```

进入 AI 时携带：

* 当前简历
* 相关岗位
* 当前 Gap
* 当前建议

# 5.7 今日一句

## 页面定位

“今日一句”是轻量级成长陪伴内容，不是核心功能。

### 目的

提供低成本、低干扰的情绪陪伴。

### 内容方向

围绕：

* 职业成长
* 能力积累
* 长期主义
* 自我认识
* 职业选择
* 下一步行动

### 不建议

大量使用：

* 鸡汤
* 成功学
* 过度激励
* 复杂 AI 生成内容

### MVP实现

第一版可以使用本地内容库：

```text
本地 JSON
↓
根据日期
↓
展示当日内容
```

不需要：

* 实时 AI 生成
* 个性化推荐算法
* 独立内容后台
* 复杂内容管理系统

---

# 5.8 岗位匹配变化

### 页面定位

首页只展示：

> **岗位匹配发生了什么变化。**

而不是再次完整展示岗位排名。

### 示例

```text
岗位匹配变化

AI 产品经理       78% → 86%   ↑8
产品经理           79% → 82%   ↑3
数据产品经理       74% → 74%    —
```

### 操作

> **查看全部 →**

可以进入：

* 分析 → 多岗位匹配结果
* 我的 → 历史分析

根据用户点击上下文决定目标。

## 6.1 页面定位

分析是 Careerly 的：

> **核心分析工作台。**

核心任务：

> **让用户看见自己与多个目标岗位之间的距离。**

---

```text

├── 当前简历

├── 添加目标岗位
│

│   ├── 变化
```

# 6.3 分析入口

```text
分析
↓
上传简历

AI解析

```

```text
分析
```

```text
首页

```

# 6.4 多岗位匹配结果页

这是 Careerly 最核心的页面之一。

### 核心任务

让用户快速回答：

> **“现在的我更接近哪个岗位？”**

### 页面结构

```text
当前简历
↓

已分析 8 个岗位

┌─────────────────────┐
│ #1 AI 产品经理       │
│ 86%                  │
│ ↑ 8%                 │
│                     │
│ 高匹配               │
└─────────────────────┘

┌─────────────────────┐
│ #2 产品经理          │
│ 82%                  │
│ ↑ 3%                 │
└─────────────────────┘

┌─────────────────────┐
│ #3 数据产品经理      │
│ 74%                  │
│ —                    │
└─────────────────────┘
```

---

# 6.5 排序规则

排序基于：

> **用户当前能力与岗位能力要求之间的匹配程度。**

允许用户直观看见：

* 当前排名
* 当前匹配度
* 排名变化
* 匹配度变化

### 重要边界

岗位排序不代表：

* 用户市场竞争力排名
* 用户与其他求职者比较
* 用户职业价值排名
* 用户薪资价值排名

---

# 6.6 实时重新分析

当用户更新简历后：

```text
旧简历
↓
新简历
↓
重新解析能力
↓
重新计算岗位匹配
↓
更新排序
↓
展示变化
```

例如：

```text
AI 产品经理
78% → 86% ↑8

产品经理
79% → 82% ↑3

数据产品经理
74% → 74% —
```

这是 Careerly 最核心的反馈机制之一。

# 6.7 岗位匹配详情页

### 核心问题

> **为什么这个岗位是这个匹配度？**

页面包括：

1. 匹配概览
2. 匹配原因
3. 能力优势
4. 能力 Gap
5. AI 需要提升的点
6. AI 行动建议

---

# 6.8 匹配概览

展示：

* 岗位名称
* 公司信息
* 匹配度
* 当前排名
* 与上次匹配度变化

例如：

```text
AI 产品经理

86%
匹配

当前排名 #1
较上次 +8%
```

---

# 6.9 匹配原因

回答：

> **为什么匹配？**

内容来源：

* 工作经历
* 项目经历
* 技能
* 成果
* 行业经验

强调：

> **能力证据。**

而不是简单列关键词。

---

# 6.10 能力优势

展示：

> 当前用户已经具备、并对岗位匹配有重要影响的能力。

例如：

```text
产品规划       高匹配
AI应用能力     高匹配
用户研究       中高匹配
项目管理       高匹配
```

---

# 6.11 能力 Gap

回答：

> **差在哪里？**

建议按照影响程度排序：

### 关键 Gap

直接影响岗位匹配。

### 一般 Gap

存在差距，但对当前岗位影响较小。

---

# 6.12 AI需要提升的点

AI 基于：

> 岗位要求 + 用户能力 + 当前 Gap

提炼最值得优先提升的 1–3 项能力。

重点：

> **不是列出所有不足，而是帮助用户识别最值得关注的能力。**

例如：

> **AI Agent 产品落地能力**

并解释：

> 当前已有 AI 产品经验，但缺少完整 Agent 项目落地证据，是当前岗位匹配中的主要 Gap。

---

# 6.13 AI行动建议

回答：

> **下一步可以做什么？**

建议必须：

* 与 Gap 对应
* 与用户当前基础对应
* 具体
* 可执行
* 尽可能能够形成新的职业资产

例如：

```text
行动建议

1. 完成一个可运行的 AI Agent 项目
2. 补充需求分析与产品设计过程
3. 记录项目结果与量化成果
4. 将项目沉淀为新的项目经历
```

页面操作：

> **和 AI 讨论 →**

跳转：

```text
分析
↓
岗位详情
↓
AI行动建议
↓
AI
```

# 7. AI｜理解与行动

## 7.1 页面定位

AI 不是一个独立于 Careerly 数据之外的普通聊天机器人。

AI 是：

> **Careerly 的理解与行动入口。**

核心问题：

> **为什么？下一步怎么办？**

---

# 7.2 AI 信息架构

```text
AI
│
├── AI职业顾问
│
├── 当前分析上下文
│   ├── 解释匹配
│   ├── 解释Gap
│   ├── 解释能力变化
│   └── 讨论行动
│
└── 对话记录
```

---

# 7.3 AI职业顾问

支持用户自然提问：

* 为什么这个岗位匹配度最高？
* 我的主要 Gap 是什么？
* 哪个能力最值得提升？
* 如果我补充这个项目，可能影响哪些岗位？
* 我应该先提升哪一项？
* 最近我的能力发生了什么变化？

---

# 7.4 上下文 AI

从其他页面进入 AI 时，应携带上下文。

例如从岗位详情进入：

```text
当前用户简历
+
当前岗位 JD
+
匹配度
+
能力模型
+
Gap
+
AI建议
```

AI 不应该要求用户重新输入这些信息。

---

# 7.5 AI对话记录

对话记录用于保留：

* 用户问题
* AI回答
* 当前上下文
* 时间

MVP阶段可以采用轻量历史记录。

不需要建立复杂知识库。

# 8. 我的｜沉淀积累

## 8.1 页面定位

“我的”不是传统意义上的个人中心。

它是：

> **Careerly 的长期职业档案与职业资产中心。**

核心问题：

> **“一路走来，我积累了什么？”**

---

# 8.2 我的信息架构

```text
我的
│
├── 职业资产
```

# 27. IA 验收标准

新的 IA 在进入高保真设计和开发前，需要满足：

* [ ] 一级导航不超过 4 个
* [ ] 用户能够理解四个一级入口的区别
* [ ] “成长”不作为独立一级导航
* [ ] 多岗位匹配排序属于“分析”核心功能
* [ ] 岗位匹配详情能够进入 AI
* [ ] AI 能够获得分析上下文
* [ ] 用户更新简历后能够重新触发岗位匹配
* [ ] 历史岗位 JD 能够自动保存
* [ ] 历史匹配结果能够被追踪
* [ ] 能力变化能够进入职业资产
* [ ] 匹配变化能够回到首页
* [ ] 首页能够形成“总 → 分 → 变化”
* [ ] 首页不重复完整展示分析结果
* [ ] “今日一句”保持轻量陪伴定位
* [ ] 职业资产不依赖用户手动维护
* [ ] 所有核心页面都能明确回答一个用户问题
* [ ] 页面之间形成完整闭环

# 28. V2.0 最终 IA 定义

Careerly 的最终一级 IA：

> **首页｜看见现在**
> **分析｜看见距离**
> **AI｜理解与行动**
> **我的｜沉淀积累**

Careerly 的两个核心可见：

> **看见我与岗位的距离。**
> **看见我自身的变化。**

Careerly 的长期循环：

> **分析 → 理解 → 行动 → 变化 → 再分析 → 沉淀。**

因此，Careerly 不是一个单纯的求职工具，也不是一个独立的 AI 聊天产品，而是一个围绕：

> **“我现在在哪里 → 我离目标有多远 → 我发生了什么变化 → 下一步可以做什么 → 这些变化如何被积累”**

建立起来的个人职业成长系统。
